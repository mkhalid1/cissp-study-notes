# Glossary

Plain-English definitions of terms used in these notes. Domain numbers show where each term is covered in depth.

| Term | Meaning | Domain |
|---|---|---|
| ABAC | Attribute-based access control: access decided by policies over attributes of user, resource, action and environment | 5 |
| AH | IPsec Authentication Header: integrity and origin authentication, no encryption | 4 |
| ALE | Annualised loss expectancy: SLE x ARO | 1 |
| ARO | Annualised rate of occurrence: expected events per year | 1 |
| Associate of ISC2 | Status for someone who passed but lacks the required experience | Overview |
| BIA | Business impact analysis: identifies critical processes, impacts and recovery targets | 1 |
| Bell-LaPadula | Confidentiality model: no read up, no write down | 3 |
| Biba | Integrity model: no read down, no write up | 3 |
| Brewer-Nash | Conflict-of-interest model, also called the Chinese Wall | 3 |
| CASB | Cloud access security broker: discovers and governs cloud service use | 2 |
| CAT | Computerized Adaptive Testing: the exam picks each item based on your previous answers | Scoring |
| CER | Crossover error rate: where false acceptance equals false rejection; lower is better | 5 |
| Chain of custody | Record of who held evidence, when and why | 7 |
| Clark-Wilson | Integrity model using approved programs and separation of duties | 3 |
| Clearing | Overwriting media so normal tools cannot recover data | 2 |
| CMM | Capability Maturity Model: five levels from Initial to Optimising | 8 |
| Common Criteria | ISO/IEC 15408 product evaluation scheme with EAL levels | 3 |
| CPE | Continuing professional education credits needed to keep the certification | Overview |
| CSRF | Cross-site request forgery: a site tricks a logged-in browser into sending a request | 8 |
| Custodian | The role, usually IT, that implements the owner's protection decisions | 2 |
| DAC | Discretionary access control: the owner decides access | 5 |
| DAST | Dynamic application security testing of a running application | 8 |
| Data controller | Decides why and how personal data is processed | 2 |
| Data processor | Processes personal data on the controller's instructions | 2 |
| Defense in depth | Layered, independent controls | 3 |
| Differential backup | Changes since the last full backup | 7 |
| DLP | Data loss prevention: detects and blocks sensitive data leaving | 2 |
| DRM | Digital rights management: controls use of a file wherever it goes | 2 |
| Due care | Doing what a reasonable person would do; operating the right controls | 1 |
| Due diligence | Investigating and verifying to know which controls are needed and working | 1 |
| Duress code | A signal that someone is being coerced | 7 |
| EAL | Evaluation Assurance Level: how rigorously a product was evaluated | 3 |
| ESP | IPsec Encapsulating Security Payload: encryption plus integrity | 4 |
| EF | Exposure factor: share of an asset lost in one event | 1 |
| FAR | False acceptance rate: impostors accepted (Type II error) | 5 |
| FRR | False rejection rate: legitimate users refused (Type I error) | 5 |
| Fuzzing | Sending malformed or random input to find crashes | 6 |
| IAST | Interactive application security testing from inside the running app | 8 |
| Incremental backup | Changes since the last backup of any type | 7 |
| JIT access | Just-in-time access: privileges granted only for an approved window | 5 |
| Kerberos | Ticket-based enterprise SSO; needs synchronised clocks | 5 |
| KRI | Key risk indicator: a warning that risk is rising | 6 |
| Least privilege | Only the access needed for the task | 1, 3, 5 |
| MAC | Mandatory access control: access set by the system using labels and clearances | 5 |
| MTD | Maximum tolerable downtime | 1 |
| NAC | Network access control: checks device identity and health before allowing access | 4 |
| Nonrepudiation | The sender cannot credibly deny sending; needs a digital signature | 1, 3 |
| OAuth 2.0 | Delegated authorisation framework using tokens | 5 |
| OpenID Connect | Authentication layer on top of OAuth 2.0 | 5 |
| Order of volatility | Collect the most short-lived evidence first | 7 |
| Pass the hash | Reusing a captured password hash to authenticate | 3 |
| PDP and PEP | Policy decision point decides; policy enforcement point carries out the decision | 5 |
| Pre-action sprinkler | Needs detection and a head to open before water flows; usual for data centres | 3 |
| Pretest items | Unscored items being trialled; 25 on every CISSP exam | Scoring |
| Privilege creep | Access building up as people change roles | 5 |
| Purging | Sanitisation that defeats lab recovery, such as degaussing or crypto erase | 2 |
| RAID 5 | Striping with parity; survives one disk failure | 7 |
| RBAC | Role-based access control | 5 |
| RPO | Recovery point objective: maximum acceptable data loss, in time | 1 |
| RTO | Recovery time objective: target time to restore | 1 |
| SAML | XML-based federation standard for enterprise web SSO | 5 |
| SAST | Static application security testing without running the code | 8 |
| SCA | Software composition analysis of third-party components | 8 |
| Scoping | Removing baseline controls that do not apply | 2 |
| SIEM | Collects and correlates logs and raises alerts | 7 |
| SLE | Single loss expectancy: AV x EF | 1 |
| SOC 2 Type II | Report on operating effectiveness of controls over a period | 6 |
| STRIDE | Threat categories: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege | 1 |
| Tailoring | Adjusting the controls that remain to fit the environment | 2 |
| TPM | Trusted Platform Module: chip that stores keys and measures boot | 3 |
| UEBA | User and entity behaviour analytics | 7 |
| WRT | Work recovery time after systems are restored | 1 |
| XSS | Cross-site scripting: injected script runs in other users' browsers | 8 |
| Zero trust | Never trust by location; verify every request | 3, 4 |
